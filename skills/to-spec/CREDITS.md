# Credits

Inspired by [Matt Pocock's `to-spec` skill](https://github.com/mattpocock/skills/tree/main/skills/engineering/to-spec): synthesising a spec from what was already discussed instead of interviewing, describing the solution from the user's point of view, keeping file paths and code out of the spec, choosing the highest test seam and naming what is out of scope. The one round of numbered questions, each with a recommended answer that "yes" accepts, follows his [`grilling`](https://github.com/mattpocock/skills/tree/main/skills/productivity/grilling) skill.

Some ideas come from Cursor's [pstack](https://github.com/cursor/plugins/tree/main/pstack) plugin (MIT): grounding the design in the code before writing it, sketching two structurally different shapes before choosing one, screening them for split state ownership, two ways to do one task and hand-synced lists, and keeping facts separate from assumptions. The writing rules follow its `technical-writing` skill.

This skill uses an independently written workflow and template; neither upstream is a runtime dependency.
